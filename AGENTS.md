# AGENTS.md

Windows desktop "图片工具箱" (Image Toolbox): a tabbed shell with **two top-level tabs**.

- **批处理** (batch): a `ToolHostPage` (left tool list + content panel) hosting 批量处理 (format conversion / resize / rename / rotate-flip / watermark) + 批量导出 (multi-size export + .ico). No shared document.
- **单图编辑** (single-image editing): a **single-canvas** editor (`SingleEditPage`) — open one image, pick an operation on the left, its controls appear on the right, and its preview renders onto the one central `ImageCanvas`; `应用到图片` commits the result (undo/redo). Operations: 基础调整 (brightness/contrast/saturation/temperature/tint), 色阶 (levels + auto), 白平衡 (sample / auto), HSL, 风格预设, 特效 (mosaic / blur / oil paint / sketch / emboss / edge / background blur / texture / glow / rounded / circle / shadow), 绘画标注 (line / arrow / pen / marker / eraser / blur / mosaic brushes / text / shapes), 变换 (move / scale / rotate the active layer), 抠图 (color-threshold / magic-wand), 裁剪 / 旋转 (crop + rotate + flip), 证件照, 取色配色 (statistics tone transfer), 局部覆盖 (feathered multi-region overlay), 颜色工具 (picker + palette, view-only), 图像对比 (side-by-side / slider / difference, view-only), 图片信息 (statistics/histogram, view-only). The editor is **layer-based**: a global 图层 `LayerPanel` manages `EditSession`'s layer stack; operations apply to the **active layer**, and the canvas shows the flattened composite.

C# WinForms UI + WPF/WIC imaging.

## Build

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Output: `ImageToolbox.exe` in the repo root. `build.ps1` compiles every `*.cs` under the repo **recursively** (via `Get-ChildItem -Recurse`), so new source files are picked up automatically regardless of folder. Always rebuild after editing `.cs` files; the `.exe` is committed/present and does not auto-update.

## Layout

Sources live under `src/` (namespace is still flat `ImageToolbox`):

- `src/App/` — shell + editor: `Program.cs`, `ToolPage.cs`, `ToolHostPage.cs`, `EditLayer.cs`, `EditSession.cs`, `LayerPanel.cs`, `SingleEditPage.cs`, `EditOpPanel.cs`, `EditOpsAdjust.cs`, `EditOpsMore.cs`, `EditOpsDraw.cs`, `EditOpsTransform.cs`.
- `src/Controls/` — custom `Control`s (`ImageCanvas`, `HistogramView`, `CurveEditor`).
- `src/Imaging/` — UI-free logic (`ImageUtil`, `ImageEffects`, `ImageFilters`, `ImageBatch`, `ImageLayout`, `ImageTuning`, `ImageMeta`, `ImageCompare`, `ImageBlend`, `ImageMatting`, `PaletteExtractor`, `MultiSizeExport`).
- `src/Pages/` — batch tab pages (`BatchProcessPage.cs`, `MultiSizeExportPage.cs`).

`app.manifest`, `app.ico`, `build.ps1` and the docs stay in the repo root.

## Toolchain constraints (easy to get wrong)

- There is **no** `dotnet` SDK, Visual Studio, `.csproj`/`.sln`, NuGet, or `nuget` on PATH. Build uses the in-box legacy compiler `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`.
- That compiler is **C# 5**. Do not use string interpolation (`$"..."`), null-conditional (`?.`), expression-bodied members, auto-property initializers, `nameof`, or other C# 6+ syntax — it will not compile.
- `build.ps1` resolves the WPF assemblies `PresentationCore`, `WindowsBase`, `System.Xaml` by searching the GAC at `C:\Windows\Microsoft.NET\assembly`. Do not replace them with simple `/r:Name.dll` references; csc cannot resolve them that way here.
- `PixelFormat` is ambiguous between `System.Drawing.Imaging` and `System.Windows.Media`. `ImageBatch.cs` and `ImageUtil.cs` disambiguate with `using PixelFormat = System.Drawing.Imaging.PixelFormat;` — keep those aliases.

## Architecture

- `ToolPage.cs` — abstract `ToolPage : UserControl` base (`ToolName`, `Shutdown`). Each batch tab page derives from it.
- `Program.cs` — `MainForm` shell: a `TabControl` (docked fill) + `Program.Main` entrypoint. It registers exactly **two** tabs, in order: `SingleEditPage` (单图编辑) first, then `ToolHostPage("批处理", …)`; `MainForm.AddTool(ToolPage)` adds a top-level tab; `OnFormClosing` calls `Shutdown` on each tab's page (hosts cascade to their children).
- `ToolHostPage.cs` — a generic `ToolPage` that hosts a group of tools: a left `ListBox` of tool names + a content `Panel`; all child pages are created up front, `Dock=Fill`, and toggled by `Visible` on selection. `Shutdown` cascades to every child. Used by 批处理.
- `EditLayer.cs` — one layer: `Name`, `Image` (always document-sized), `Visible`, `Mode` (`BlendMode`), `Opacity`, `Offset` (position on the canvas; content moved off-canvas is preserved), plus `Clone`/`Dispose`.
- `EditSession.cs` — the shared **layer stack** (internal index 0 = bottom, count-1 = top; `ActiveIndex`/`ActiveLayer`; doc `Width`/`Height`). `SetOriginal` makes one `背景` layer; `Composite()` flattens visible layers in place via `ImageBlend.CompositeInto` (one accumulator, no per-layer bitmaps); `CompositePreview(...)` does the same at preview scale with a **self-validating per-layer preview cache** (each entry remembers the layer `Image` reference + max size, so previews are regenerated only for the layer whose image actually changed; add/remove/reorder/opacity/mode/visibility/offset changes reuse every other layer's preview and stale entries are pruned), and `IsSoloNormalActive` lets the editor skip compositing when a single normal/opaque/offset-free layer is shown. `PreviewOf(layer, maxSize)` is `internal` so the editor can *borrow* the cached downscale for its `PreviewSource` instead of rescaling the full-res layer again. History is **per-layer**: `CommitToActive` records a `PixelCommand` holding only that layer's before/after, `CommitDocument` replaces the whole document (flattens to one 背景), structure/prop edits (add/remove/reorder/merge/stamp/flatten/visibility/mode/opacity) record `StructureCommand`/`MergeDownCommand`/`PropsCommand`, and layer moves record `MoveCommand` via `CommitOffset` (each layer's `Offset` shifts it without discarding pixels). `Undo`/`Redo`/`ResetToOriginal`/`DisposeAll`. 16-step history.
- `LayerPanel.cs` — the global 图层 panel (right column, under the op panel): layer list (top layer first, `●/○` visibility mark + mode + opacity), 添加图片 / 新建 / 复制 / 删除 / 上移 / 下移 / 向下合并 / 盖印 / 拼合 buttons, plus a 显示 checkbox, blend-mode combo and opacity slider. Raises `LayersChanged` so the editor re-attaches the active op and recomposites. A draggable `Splitter` sits above the panel (in `SingleEditPage`'s right column) so its height is adjustable (min 220px); the layer list is dock-filled so it grows/shrinks with the panel.
- `SingleEditPage.cs` — the `"单图编辑"` tab: a top toolbar (打开图片 / 新建 / 保存为 PNG / **应用到图片** / 撤销 / 重做 / 复位; 新建 opens `NewImageDialog` for width/height + white/transparent background and calls `EditSession.SetOriginal` with a blank bitmap, leaving `_sourcePath` null), a left `ListBox` of operations, the central `ImageCanvas`, and a right column with the operation panel over the global `LayerPanel`. Open calls `EditSession.SetOriginal`; `RefreshPreviewSource` sets `Source` to the **active layer** (or the flattened composite for `DocumentLevel` ops) and `PreviewSource` to its downscale; selecting an operation re-attaches it (`EditOpPanel.Attach(opSource, previewSource, canvas)`); when an op raises `PreviewInvalidated` the editor debounces then `ComputePreview` composites the preview (layer ops: `op.RenderPreview()`/active layer blended over the other layers via `session.CompositePreview`; `DocumentLevel`/view-only: the op preview directly); `应用到图片` calls `session.CommitToActive(op.BuildResult())` for layer ops or `session.CommitDocument(...)` for document ops, then calls `op.ResetState()` (each op returns its controls to a neutral/identity state, e.g. effect "无", sliders default, clear brush strokes/regions) so the effect is **not re-applied** on the next preview. Canvas mouse events are converted from displayed-image pixels to session pixels via the display scale before being dispatched to the active op (`OnCanvasClick`/`OnCanvasSelection`/`OnBrushPoint`) — **ops must use the dispatched coordinates, never read `Canvas.Selection` directly** (it is in displayed-image pixels, so on a downscaled preview it would be mispositioned); `BrushRadiusSession` is scaled to set `ImageCanvas.BrushRadius`. Undo/redo/reset reload the active op. For an op with `WantsCanvasDrag` (变换), `ReloadAll` puts the canvas in drag mode and the `DragStarted`/`Moved`/`Finished` events dispatch to `op.OnCanvasDrag(point, 0/1/2)` via `DispatchDrag` (layer-space coords). Canvas coordinates are mapped into the active layer's space (`ToLayer` subtracts the layer `Offset`) for click/brush/drag dispatch. Switching operations while the active op has an unapplied result (tracked by `_opDirty`, set on any user `PreviewInvalidated` with `_suppressDirty` off and cleared on apply) shows a Yes/No/Cancel prompt — apply-and-switch / discard (reset the op) and switch / cancel (revert the list selection).
- `EditOpPanel.cs` — base for a single-canvas operation (`Source` full-res + `PreviewSource` downscaled + shared `Canvas`; `Attach`/`Detach`; `OnActivate`/`OnDeactivate`; `RenderPreview`/`BuildResult`/`CanApply`; `LivePreview` (true ⇒ the editor renders immediately on every change instead of debouncing, used by the brush); `DocumentLevel` (true ⇒ the op edits the whole document — `Source` is the composite and apply replaces the document instead of the active layer; used by crop/canvas/id-photo/slice); canvas dispatch overrides; `RequestApply`/`ApplyRequested` for buttons that commit immediately; `ReusablePreview` (true ⇒ `RenderPreview` returns a bitmap the op still owns, so the editor shows it without copying/disposing — used by the brush); `WantsCanvasDrag` + `OnCanvasDrag(point, 0/1/2)` (true ⇒ the editor puts the canvas in drag mode and dispatches drags to the op — used by 变换); `ResetState`; `DisposeResources`). `EditOpUi` is a small control-factory helper (Title/Caption/Slider/Combo/Button/Note) used by op constructors.
- `EditOpsAdjust.cs` — ops `BasicAdjustOp` (brightness/contrast/saturation/temperature/tint), `LevelsOp` (black/white/gamma + `AutoLevels`), `WhiteBalanceOp` (canvas sample / `AutoWhiteBalance`), `HslOp`, `StyleOp` (presets + strength), `EffectsOp` (13 `ImageFilters` effects).
- `EditOpsTone.cs` — ops `CurveOp` (per-channel `CurveEditor` → `TuningState.CurvePoints`), `LocalMaskOp` (radial/linear local mask, canvas-click center), `ToningOp` (posterize / duotone / gradient map), `LutOp` (`.cube` via `ImageTuning.TryLoadCube`), `CanvasOp` (straighten/auto-crop + canvas extend/crop with anchor).
- `EditOpsMore.cs` — ops `MattingOp`, `CropOp` (crop / exact 90° rotate / flip; tiled buttons that apply immediately via `RequestApply` so repeated clicks accumulate, plus a `RequestReset` button that restores the image snapshot taken when the tool was entered — `EditOpPanel.WantsEntrySnapshot`), `IdPhotoOp` (single photo + sheet tiling via `ImageLayout.BuildSheet`), `ColorMatchOp` (reference image + `EstimateAdjustment`), `LocalOverlayOp` (multi-region feathered overlay; 覆盖位置 = 相对 maps the selection proportionally onto the overlay (crop) then scales that piece back to the base selection — handles overlays larger/smaller than the base; 绝对 uses the selection's exact pixel rect 1:1 to crop the overlay and paste at the same base position, no scaling), plus view-only `ColorToolOp`, `CompareOp`, `InfoOp` (`CanApply == false`).
- `EditOpsSlice.cs` — op `SliceCollageOp` (grid slice export via `ImageLayout.Slice`; collage with direction/columns/spacing/long-edge/background via `ImageLayout.Collage`).
- `EditOpsDraw.cs` — op `DrawOp` (绘画 / 标注): tools 直线/箭头/画笔/记号笔/橡皮擦/模糊/马赛克/文字/形状 (矩形/圆角矩形/椭圆/三角形/五角星), with color picker, 粗细, 强度 (模糊半径 / 马赛克块大小), 字号, 填充 and 撤销一笔/清除全部. Two kinds of strokes: **vector items** (line/arrow/pen/marker/text/shapes, recorded in **source coordinates** and re-rendered both in preview and at 1:1 on apply) and **raster effects** (eraser/blur/mosaic, applied to a persistent `_committed` bitmap of the base via a soft brush mask — preview blends only the dirty rect, `BuildResult` **replays** the effect strokes at full res grouped by (kind, strength) so each group's blur/mosaic runs once). `_work` (= `_committed` + vector items, `ReusablePreview` so the editor shows it without owning it) is recomposed via `ComposeWork`; `RenderPreview` returns it and `BuildResult` clones `Source`, applies effects, then draws the vector items on top. Uses the canvas brush events (`OnBrushPoint`, `LivePreview`). 文字 uses **in-canvas editing**: clicking overlays a **multiline** `CanvasTextBox` (an internal `TextBox` subclass that is truly transparent — it handles `WM_ERASEBKGND` by calling `ImageCanvas.PaintView` to draw the parent canvas image into its own DC, and the canvas handles `WM_CTLCOLOREDIT`/`STATIC` returning `NULL_BRUSH` so the edit never fills its own background) on the canvas plus a small ✓/✕ button pair (positioned via `ImageCanvas.ImageToClient`, font scaled by `ViewScale`); `Enter` inserts a newline, **✓ commits** into a text item (`✕`/`Esc` cancels). Blur no longer commits (so ✕ works); clicking elsewhere commits the previous box, switching ops commits silently (`CommitTextEditCore`), and apply/reset discards it. `Canvas.TextEditing` suppresses Space-pan while typing and `ViewChanged` repositions the box on zoom/pan. Note: don't dispose the old `Control.Font` when reassigning an *equal* font — WinForms ignores the assignment and you'd free the in-use font.
- `EditOpsTransform.cs` — op `TransformOp` (变换): move the active layer by dragging on the canvas (`WantsCanvasDrag`; `OnCanvasDrag` accumulates `_dx/_dy` in source px) plus `缩放` (10–400%) and `旋转` (−180–180°) sliders, applied about the layer centre via `Graphics` translate/rotate/scale; `RenderPreview` returns `null` at identity (so the editor shows the composite) and `BuildResult` returns the transformed layer bitmap (content pushed outside the canvas is clipped); 重置 returns to identity.
- `BatchProcessPage.cs` — the `"批量处理"` tool page (file list/thumbnails + a scrollable options panel: 输出格式 / 尺寸 / 旋转翻转 / 重命名 / 水印). Processing and thumbnails each run in their own `BackgroundWorker`. `BuildOptions()` snapshots the UI into a `BatchOptions` on the UI thread; the worker only touches that snapshot. A watermark image is preloaded on the UI thread and disposed in the worker's `finally`.
- `ImageEffects.cs` — `ColorMatrix` builders (`Brightness`, `Contrast`, `Saturation`, `Temperature`, `Tint`, `Grayscale`, `Sepia`, `Multiply`) and `PresetMatrix(name)`; in-place spatial effects (`Vignette`, `Soften`, `Sharpen`, `Grain`, `LightLeak`, `Frame`) that expect a 32bppArgb bitmap; and statistics (`ColorStats`/`MeasureStats`/`EstimateAdjustment`/`MatrixFromParams`) for color matching.
- `ImageFilters.cs` — no WinForms/WPF UI deps; heavier pixel filters operating on 32bppArgb bitmaps: `Clone`, `Mosaic`, `GaussianBlur` (3× separable `BoxBlur`), `MotionBlur`, `OilPaint`, `Sketch`, `Emboss`, `EdgeDetect`, `BackgroundBlur` (radial clear-zone blend), `Paper`, `Glow` (bright-pass + screen), `RoundedCorners`, `Circle` and `DropShadow` (both return new bitmaps), and `MaskBlend(base, effect, mask)` which lerps toward `effect` by the mask's alpha channel (used by `DrawOp`'s blur/mosaic brushes and `LocalOverlayOp`). `CopyPixels`/`PastePixels` are the LockBits helpers.
- `ImageUtil.cs` — generic WIC-backed image helpers: `LoadImage`, `CreatePreview` (downscales with `HighQualityBilinear` — much faster than bicubic and the difference is invisible after the canvas rescale), `LoadThumbnail`, `Compose`, `MapRegion`, `ApplyColorMatrix`, `SavePng`, private `ToBitmap`. Always converts to `Bgra32` before copying pixels, so opaque images don't end up with alpha 0.
- `ImageCanvas.cs` — custom `Control` that displays an image letterboxed over a gray/white checkerboard (so transparent pixels read as transparent); the image/checker are painted in `OnPaintBackground` (not `OnPaint`) so a `WS_EX_TRANSPARENT` child control (the draw op's transparent text box) reveals the image behind it, and `OnPaint` draws only the selection/brush overlays and supports rubber-band selection in image pixel coordinates (`ReadOnly` mode shows a non-editable selection); `LockAspect > 0` constrains the selection to a fixed width/height ratio; `PixelClicked` reports the clicked image-pixel coordinate (used for white-balance sampling and local-mask center). `BrushEnabled` switches mouse handling to freehand painting: `BrushStarted`/`BrushMoved`/`BrushFinished` report image-pixel points, and a `BrushRadius` (in displayed-image pixels) circle follows the cursor. `DragEnabled` switches to drag-to-move (`SizeAll` cursor): `DragStarted`/`DragMoved`/`DragFinished` report image-pixel points. Selection, brush and drag modes are mutually exclusive. View transform: mouse wheel zooms (`_zoom`, cursor-anchored, clamped 0.1–16×) and holding **Space** + left-drag (or middle-drag) pans (`_panX/_panY`, clamped to the image edges) — implemented via `ComputeLayout()` which derives `_scale = fit*_zoom` and `_imageRect` from zoom+pan; `ZoomEnabled=false` disables it (used by the overlay thumbnail). A global `IMessageFilter` watches the Space key only while the mouse is over the canvas (skipped while `TextEditing`); `ImageToClient`/`ViewScale`/`ViewChanged` let an op overlay controls (e.g. the draw op's text box) and keep them aligned on zoom/pan; the view resets when the image size changes but survives same-size preview refreshes. `SetImage` compares against a remembered `_lastImageW/H` (never reads `_image`, which the editor may already have disposed).
- `ImageBatch.cs` — no WinForms/WPF UI deps; the batch pipeline: `Run` (per-file entry point), `Resize`, `GetExifOrientation`/`ApplyOrientation`, `BuildName`/`ResolveTargetPath` (collision-safe), `DrawWatermark` (text/image, nine-grid, tiling, opacity, rotation), and `Save` (PNG/JPG/BMP/GIF/TIFF, JPEG quality, transparency flattening).
- `ImageLayout.cs` — no WinForms/WPF UI deps; composition logic: `Crop`, `Rotate`/`LargestInscribed` (straighten), `ExtendCanvas`, `Slice`, `Collage`, `BuildIdPhoto`/`BuildSheet`, `DrawInBox`. Used by `CropOp`/`IdPhotoOp` (and the batch/export pages).
- `ImageTuning.cs` — no WinForms/WPF UI deps; `Histogram`, `AutoLevels`, `AutoWhiteBalance`, `WhiteBalanceFromColor`, `BuildCurveLut` (monotone cubic), `Apply` (one per-pixel pass for white balance/levels/curve/HSL/toning + a second pass for the local mask; a default `TuningState` is the identity), `TryLoadCube` and 3D trilinear LUT sampling, gradient presets. Used by `LevelsOp`/`WhiteBalanceOp`/`HslOp`/`InfoOp`.
- `HistogramView.cs` / `CurveEditor.cs` — custom `Control`s for the histogram display and draggable curve editing (add/drag/right-click-delete control points).
- `ImageMeta.cs` — WIC `BitmapDecoder`/`BitmapMetadata` helpers (`ReadInfo`, `ReadMetadata` via `CameraManufacturer` + `/app1/ifd/...` `GetQuery`, all guarded, and `StripMetadata` re-encodes via `ImageBatch.Save`).
- `ImageCompare.cs` — pure `SideBySide`/`Slider`/`Difference` compositors (used by `CompareOp`).
- `ImageBlend.cs` — `Blend(base, overlay, BlendMode, opacity)` scales the overlay to the base and applies one of 11 blend modes per pixel (keeps base alpha); `Composite(base, overlay, BlendMode, opacity)` is the alpha-correct source-over version (used by `MergeDown`); `CompositeInto(acc, overlay, …)` is the in-place variant that blends the overlay **into** `acc` (which doubles as base and output) using two per-thread reusable scratch buffers, so `EditSession.Composite`/`CompositePreview` allocate one accumulator and blend each layer in place (no per-layer bitmap/GC churn); an offset overload places the overlay at `(offsetX, offsetY)` first (used for live layer-move preview).
- `ImageMatting.cs` — `ByColor` (global threshold) and `MagicWand` (4-connected flood fill) set alpha 0 (or invert); tolerance = max per-channel distance (used by `MattingOp`, which previews/keeps real alpha so the canvas checkerboard shows through).
- `PaletteExtractor.cs` — median-cut `Extract` on a sampled bitmap + `RgbToHsv`/`Hex` (used by `ColorToolOp`).
- `MultiSizeExport.cs` + `MultiSizeExportPage.cs` — the `"批量导出"` tool page; `ComputeSize` (fit/stretch), `ResizeTo`, and `WriteIco` (writes a multi-size .ico with PNG-compressed entries). The page collects files (buttons + drag-drop), size checkboxes, format, and exports each file to each size plus an optional `.ico`.
- Adding a new single-image operation: subclass `EditOpPanel`, add it to `SingleEditPage._ops` and the parallel `names` array; implement `RenderPreview`/`BuildResult` (+`CanApply`) and any canvas dispatch. Layer ops edit the active layer (same doc size); override `DocumentLevel` only if the op changes the document size/whole-document layout. Adding a new batch tool: subclass `ToolPage` and add it to the `ToolHostPage("批处理", …)` array in `MainForm`. Namespace is `ImageToolbox`.
- WebP decoding uses **WIC** (`BitmapDecoder` / `BitmapImage`), not `System.Drawing`. GDI+ has no WebP codec: `Image.FromFile("*.webp")` throws `OutOfMemoryException`. Do not switch to System.Drawing for decoding.
- Decoding depends on the OS WebP WIC codec (built into Windows 11; Windows 10 needs the "WebP Image Extensions" Store package).
- WPF imaging objects must stay on the thread that creates them. `LoadThumbnail` runs on the worker thread and hands back only a `System.Drawing.Bitmap`.

## DPI / manifest

- `app.manifest` is embedded via `/win32manifest` for DPI awareness and must stay wired into `build.ps1`. Without it, Windows bitmap-stretches the window and text is blurry at 125%/150% scaling.
- `app.ico` is embedded via `/win32icon`; `MainForm` also sets its title-bar icon from `ExtractAssociatedIcon`. Regenerate the `.ico` with Pillow if needed.
- All controls use `AutoScaleMode.None` (WinForms auto-scaling off). Instead `DpiScaler.Apply(root, scaleRootSize)` runs in `MainForm.OnLoad` (and `NewImageDialog.OnLoad`, with `scaleRootSize=true`): it reads the real DPI (`root.CreateGraphics().DpiX`) and, when ≠ 96, recursively multiplies every control's `Location`/`Size`/`Padding`/`Margin`/`MinimumSize`, docked thicknesses, and `TableLayoutPanel` absolute row/column styles by `dpi/96` — but **not** `Font` (a 9pt font already renders 2× at 200% DPI, so scaling it again would double). This is deterministic and avoids the WinForms `AutoScaleMode.Dpi` pitfalls (nested `UserControl`s double-scaling, or not scaling at all) that clipped/overlapped controls at 200%.

## Verification

- No test suite, CI, linter, or formatter exists. There is no `dotnet test`.
- Verify changes by building (`build.ps1`) and launching `ImageToolbox.exe`.
- For headless logic checks, reference the built `ImageToolbox.exe` (copy it next to the temp harness `.exe` so it resolves at runtime) and call `ImageBatch`/`ImageUtil` from a temporary console harness; do not add test files to the repo.
- Console output for Chinese text may appear as mojibake on this machine; source files and `使用说明.md` are UTF-8 and should stay UTF-8.
