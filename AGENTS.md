# AGENTS.md

Windows desktop "图片工具箱" (Image Toolbox): a tabbed shell with **two top-level tabs**.

- **批处理** (batch): a `ToolHostPage` (left tool list + content panel) hosting 批量处理 (format conversion / resize / rename / rotate-flip / watermark) + 批量导出 (multi-size export + .ico). No shared document.
- **单图编辑** (single-image editing): a **single-canvas** editor (`SingleEditPage`) — open one image, pick an operation on the left, its controls appear on the right, and its preview renders onto the one central `ImageCanvas`; `应用到图片` commits the result (undo/redo). Operations: 调色 (a single-row TabControl grouping 基础 / 色阶 / 曲线 / 白平衡 / HSL / LUT / 色调), 局部调整 (radial/linear mask), 风格预设, 特效 (mosaic / blur / oil paint / sketch / emboss / edge / background blur / texture / glow / rounded / circle / shadow), 绘画标注 (line / arrow / pen / marker / eraser / blur / mosaic brushes / text / shapes), 变换 (move / scale / rotate the active layer), 抠图 (color-threshold / magic-wand), 选区 (rect / ellipse / brush / lasso / polygon / magnetic marquee + delete/fill/copy/cut/paste), 裁剪 / 旋转 (crop + rotate + flip), 证件照, 取色配色 (statistics tone transfer), 局部覆盖 (feathered multi-region overlay), 颜色工具 (picker + palette, view-only), 图像对比 (side-by-side / slider / difference, view-only), 图片信息 (statistics/histogram, view-only). The editor is **layer-based**: a global 图层 `LayerPanel` manages `EditSession`'s layer stack; operations apply to the **active layer**, and the canvas shows the flattened composite.

C# WinForms UI + WPF/WIC imaging.

## Build

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Output: `ImageToolbox.exe` in the repo root. `build.ps1` compiles every `*.cs` under the repo **recursively** (via `Get-ChildItem -Recurse`), so new source files are picked up automatically regardless of folder. Always rebuild after editing `.cs` files; the `.exe` is committed/present and does not auto-update.

## Layout

Sources live under `src/` (namespace is still flat `ImageToolbox`):

- `src/App/` — shell + editor: `Program.cs`, `ToolPage.cs`, `ToolHostPage.cs`, `EditLayer.cs`, `EditSession.cs`, `LayerPanel.cs`, `HistoryPanel.cs`, `SingleEditPage.cs`, `EditOpPanel.cs`, `EditOpsAdjust.cs`, `EditOpsTone.cs`, `EditOpsColorGrade.cs`, `EditOpsSlice.cs`, `EditOpsMore.cs`, `EditOpsDraw.cs`, `EditOpsSelect.cs`, `EditOpsTransform.cs`, `DpiScaler.cs`, `LayoutCompact.cs`.
- `src/Controls/` — custom `Control`s (`ImageCanvas`, `HistogramView`, `CurveEditor`) plus `BufferedListHost` (a `Panel` with `WS_EX_COMPOSITED` used to wrap the left function/tool `ListBox`). A plain `ListBox` erases and repaints its **entire** client on focus loss (which happens the first time you click a dropdown on the page, since the left list still had focus), so a tall list visibly flashes; compositing the wrapping host hides that intermediate erase. Do not put `WS_EX_COMPOSITED` directly on the native `LISTBOX` window class — `CreateWindowEx` fails with "Error creating window handle".
- `src/Imaging/` — UI-free logic (`ImageUtil`, `ImageEffects`, `ImageFilters`, `ImageBatch`, `ImageLayout`, `ImageTuning`, `ImageMeta`, `ImageCompare`, `ImageBlend`, `ImageMatting`, `PaletteExtractor`, `MultiSizeExport`).
- `src/Pages/` — batch tab pages (`BatchProcessPage.cs`, `MultiSizeExportPage.cs`).

`app.manifest`, `app.ico`, `build.ps1` and the docs stay in the repo root.

## Toolchain constraints (easy to get wrong)

- There is **no** `dotnet` SDK, Visual Studio, `.csproj`/`.sln`, NuGet, or `nuget` on PATH. Build uses the in-box legacy compiler `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`.
- That compiler is **C# 5**. Do not use string interpolation (`$"..."`), null-conditional (`?.`), expression-bodied members, auto-property initializers, `nameof`, or other C# 6+ syntax — it will not compile.
- `build.ps1` resolves the WPF assemblies `PresentationCore`, `WindowsBase`, `System.Xaml` by searching the GAC at `C:\Windows\Microsoft.NET\assembly`. Do not replace them with simple `/r:Name.dll` references; csc cannot resolve them that way here.
- `PixelFormat` is ambiguous between `System.Drawing.Imaging` and `System.Windows.Media`. `ImageBatch.cs` and `ImageUtil.cs` disambiguate with `using PixelFormat = System.Drawing.Imaging.PixelFormat;` — keep those aliases.

## Architecture

- `ToolPage.cs` — abstract `ToolPage : UserControl` base (`ToolName`, `Shutdown`). Each batch tab page derives from it.
- `Program.cs` — `MainForm` shell: a `TabControl` (docked fill) + `Program.Main` entrypoint. It registers exactly **two** tabs, in order: `SingleEditPage` (单图编辑) first, then `ToolHostPage("批处理", …)`; `MainForm.AddTool(ToolPage)` adds a top-level tab; `OnFormClosing` calls `Shutdown` on each tab's page (hosts cascade to their children). **Do not set `WindowState = FormWindowState.Maximized` in the constructor** — maximizing before the handle exists makes the Windows taskbar button show a blank icon (title bar/Explorer/Task Manager are fine; only the running window's taskbar button loses its icon). Maximize in `OnShown` instead.
- `ToolHostPage.cs` — a generic `ToolPage` that hosts a group of tools: a left `ListBox` of tool names + a content `Panel`; all child pages are created up front, `Dock=Fill`, and toggled by `Visible` on selection. `Shutdown` cascades to every child. Used by 批处理.
- `EditLayer.cs` — one layer: `Name`, `Image` (always document-sized), `Visible`, `Mode` (`BlendMode`), `Opacity`, `Offset` (position on the canvas; content moved off-canvas is preserved), `LockTransparent` (锁定透明像素) / `LockImage` (锁定图像像素), plus `Clone`/`Dispose`.
- `EditSession.cs` — the shared **layer stack** (internal index 0 = bottom, count-1 = top; `ActiveIndex`/`ActiveLayer`; doc `Width`/`Height`). `SetOriginal` makes one `背景` layer; `Composite()` flattens visible layers in place via `ImageBlend.CompositeInto` (one accumulator, no per-layer bitmaps); `CompositePreview(...)` does the same at preview scale with a **self-validating per-layer preview cache** (each entry remembers the layer `Image` reference + max size, so previews are regenerated only for the layer whose image actually changed; add/remove/reorder/opacity/mode/visibility/offset changes reuse every other layer's preview and stale entries are pruned; a Normal+opaque layer is composited with GDI+ native source-over via `Graphics.DrawImage` — an order of magnitude faster than per-pixel and what keeps 绘画 on a non-solo layer smooth — while other modes/opacity fall back to `ImageBlend.CompositeInto`), and `IsSoloNormalActive` lets the editor skip compositing when the **active** layer is the single visible normal/opaque/offset-free layer (the active must itself be visible). For live drawing on a non-solo stack it caches `_bgBelow`/`_bgAbove` (composites of the visible layers **below**/**above** the active one, invalidated by an internal `_version` bumped in `Notify`) and `CompositePreviewOver(buffer, layerIndex, replacement, maxSize, dirty, whole)` composes below + active + above into a **caller-owned reused buffer** (a hidden active layer is not drawn); when the active layer is Normal/opaque/offset-free and `whole=false` it only redraws the `dirty` region (an `ImageCanvas` clip) — so a brush stroke only recomposites its own pixels on **any** layer, top or not. `_bgAbove` is only built when every visible layer above is Normal/opaque/offset-free (a blend-mode/translucent layer above needs the real backdrop, so it can't be pre-merged): the editor checks `CanReuseComposite(activeIndex)` and otherwise falls back to the ordered `CompositePreview`. `PreviewOf(layer, maxSize)` is `internal` so the editor can *borrow* the cached downscale for its `PreviewSource` instead of rescaling the full-res layer again. With the active layer's `LockImage` set, `CommitToActive` discards the result (no pixel change); with `LockTransparent` set it overwrites the result's alpha with the layer image's alpha via `ApplyAlphaLock` (透明处保持透明、alpha 不变). `SetLockTransparent`/`SetLockImage` go through `PushProps` (a `PropsCommand`), and `LayerState` carries the lock flags so structure undo/redo preserves them. History is **per-layer**: `CommitToActive` records a `PixelCommand` holding only that layer's before/after, `CommitDocument` replaces the whole document (flattens to one 背景), structure/prop edits (add/remove/reorder/merge/stamp/flatten/visibility/mode/opacity) record `StructureCommand`/`MergeDownCommand`/`PropsCommand`, and layer moves record `MoveCommand` via `CommitOffset` (each layer's `Offset` shifts it without discarding pixels). `Undo`/`Redo`/`ResetToOriginal`/`DisposeAll`. Every command carries a `Label` (passed by the commit callers, e.g. 图层按钮名/操作名); `HistoryCount`/`CurrentHistoryIndex`/`HistoryLabel(i)` expose the timeline (`[初始] + _undo + reverse(_redo)`) and `JumpTo(i)` walks it with repeated `Undo`/`Redo` — this backs `HistoryPanel`. 50-step history (each `PixelCommand` holds two full-layer bitmaps, so memory scales with image size × steps).
- `LayerPanel.cs` — the global 图层 panel (right column, under the op panel): layer list (top layer first; **owner-drawn** (`DrawMode.OwnerDrawVariable`): a checkbox-style visibility box — blue filled + white ✓ when visible, empty box with a diagonal slash when hidden (on a selected row the visible state is drawn as outline + ✓ so it stays legible on the highlight) — plus name + mode + opacity, hidden layers in gray), 添加图片 / 新建 / 复制 / 删除 / 上移 / 下移 / 向下合并 / 盖印 / 拼合 buttons, plus a blend-mode combo, opacity slider and two lock checkboxes (锁定透明像素 / 锁定图像像素, applying to the active layer via `EditSession.SetLockTransparent`/`SetLockImage`; toggling one fires `PropsChanged` so the current op preview recomputes under the lock). The layer list has a **right-click context menu**: 隐藏/显示图层 (toggles the clicked layer's visibility; the item text reflects the state) and 重命名… (opens `RenameLayerDialog`, calls `EditSession.Rename`). Raises `LayersChanged` so the editor re-attaches the active op and recomposites (a pending op result then follows the new active layer, since `Attach` rebuilds the preview from the new layer's base and replays the op's own state). A draggable `Splitter` sits above the panel (in `SingleEditPage`'s right column) so its height is adjustable (min 220px); the layer list is dock-filled so it grows/shrinks with the panel.
- `HistoryPanel.cs` — the 历史 tab, a read-only owner-drawn `ListBox` mirroring `EditSession`'s timeline (`[初始] + _undo + reverse(_redo)`): each row is `序号 + Label`, the current step is marked `▶` and selected, and clicking a row raises `JumpRequested(index)`. `Bind(session)` subscribes to `EditSession.Changed` so any commit/undo/redo/jump refreshes it (guarded by `_updating` so programmatic selection raises no jump). The 回到最初 button jumps to index 0.
- `SingleEditPage.cs` — the `"单图编辑"` tab: a top toolbar (打开图片 / 新建 / 保存为 PNG / **应用到图片** / 撤销 / 重做 / 复位; 新建 opens `NewImageDialog` for width/height + white/transparent background and calls `EditSession.SetOriginal` with a blank bitmap, leaving `_sourcePath` null), a left `ListBox` of operations, the central `ImageCanvas`, and a right column with the operation panel over a bottom `TabControl` whose 图层 tab holds the global `LayerPanel` and whose 历史 tab holds `HistoryPanel` (both share the draggable splitter; `HistoryPanel.JumpRequested` calls `session.JumpTo(i)` then `ReloadAll`/`LayerPanel.Sync`). Open calls `EditSession.SetOriginal`; `RefreshPreviewSource` sets `Source` to the **active layer** (or the flattened composite for `DocumentLevel` ops) and `PreviewSource` to its downscale; selecting an operation re-attaches it (`EditOpPanel.Attach(opSource, previewSource, canvas)`); when an op raises `PreviewInvalidated` the editor debounces (120 ms `_previewTimer`) then `ComputePreview` composites the preview (layer ops honor the active layer's locks: `LockImage` drops the op preview, `LockTransparent` masks the preview alpha by the layer preview via `EditSession.ApplyAlphaLock`, so 预览与最终应用一致; layer ops: `op.RenderPreview()`/active layer blended over the other layers via `ComposeLayerPreview` → `session.CompositePreviewOver` into the reused `_composeBuffer`, which caches the other layers and — when the op reports `TryGetPreviewDirtyRect` — only recomposites that dirty rect — when `session.CanReuseComposite` (every visible layer above is Normal/opaque/offset-free), else it uses the ordered `session.CompositePreview` (`_composeValid` forces a full pass after any layer/op change, and the `PropsChanged` handler also clears it since visibility/mode/opacity change the background; solo normal layers skip compositing entirely so `_work` is shown directly); `DocumentLevel`/view-only: the op preview directly; an op with no actual pixel change — `RenderPreview` is `null` (选区/颜色工具/图片信息, 变换 at identity) or `HasPendingResult` is false (调色 at defaults, 绘画标注 with no strokes, 特效「无」, etc.) — instead shows the flattened `session.Composite()` downscaled with `CreatePreview` — compositing at full-res then downscaling matches 盖印/导出 exactly, whereas per-layer downscale+composite would blend a transparent layer's downscaled edge with the background and leave a 1px white fringe inside a pasted region); for a `LivePreview` op it instead **throttles** through a 15 ms `_liveTimer` (`_livePending`: a pending tick is not reset by new invalidations, so a continuous drag still refreshes ~60 fps instead of saturating the UI thread — the transform box follows the pointer because the overlay is drawn from the op's live state); `应用到图片` calls `session.CommitToActive(op.BuildResult())` for layer ops or `session.CommitDocument(...)` for document ops (a plain layer op is refused with a status message when the active layer has `LockImage`; document-level / 复制到新图层 bypass the lock), then calls `op.ResetState()` (each op returns its controls to a neutral/identity state, e.g. effect "无", sliders default, clear brush strokes/regions) so the effect is **not re-applied** on the next preview. Canvas mouse events are converted from displayed-image pixels to session pixels via the display scale before being dispatched to the active op (`OnCanvasClick`/`OnCanvasSelection`/`OnBrushPoint`/`OnCanvasHover`/`OnCanvasDoubleClick`) — **ops must use the dispatched coordinates, never read `Canvas.Selection` directly** (it is in displayed-image pixels, so on a downscaled preview it would be mispositioned); `BrushRadiusSession` is scaled to set `ImageCanvas.BrushRadius`. Undo/redo/reset reload the active op. For an op with `WantsCanvasDrag` (变换), `ReloadAll` puts the canvas in drag mode and the `DragStarted`/`Moved`/`Finished` events dispatch to `op.OnCanvasDrag(point, 0/1/2)` via `DispatchDrag` (layer-space coords). For a `WantsTransformBox` op (变换) it also wires `ImageCanvas.OverlayPainter` to draw the op's box and `ImageCanvas.CursorProvider` to pick the hover cursor, using `LayerToClient` to map layer coords → canvas client coords (adds the layer `Offset`, divides by `DisplayScale`). Canvas coordinates are mapped into the active layer's space (`ToLayer` subtracts the layer `Offset`) for click/brush/drag dispatch. Switching operations while the active op has an unapplied result (tracked by `_opDirty`, set on any user `PreviewInvalidated` with `_suppressDirty` off and cleared on apply; the prompt also requires `op.HasPendingResult`, which defaults true) shows a Yes/No/Cancel prompt — apply-and-switch / discard (reset the op) and switch / cancel (revert the list selection). Changing the active layer (select/add/remove/reorder/merge/stamp/flatten via `LayerPanel`) first raises `ActiveLayerChanging` (`EventHandler<LayerChangingEventArgs>`; `AddsLayer` marks the 新建 button); `SingleEditPage` answers it with `ResolvePendingEdits()` — if the active op has an unapplied result (`_opDirty && CanApply && HasPendingResult`; `HasPendingResult` defaults true but `TransformOp` overrides it to `!IsIdentity()` so a plain canvas click doesn't count) it prompts 应用/放弃/取消 (apply commits to the current layer, 放弃 calls `op.ResetState()`, 取消 cancels the layer change and the list selection is restored via `Sync()`). This prevents a pending state (e.g. 变换) from silently carrying over to the newly selected layer; the one exception is the 新建 button when the active op returns `CarriesOverToAddedLayer` (only 绘画/标注) — then no prompt is shown and the pending strokes automatically follow to the new layer.
- `EditOpPanel.cs` — base for a single-canvas operation (`Source` full-res + `PreviewSource` downscaled + shared `Canvas`; `Attach`/`Detach`; `OnActivate`/`OnDeactivate`; `RenderPreview`/`BuildResult`/`CanApply`; `LivePreview` (true ⇒ the editor renders immediately on every change instead of debouncing, used by the brush); `ImmediatePreview` (true ⇒ a `LivePreview` op refreshes **synchronously** on every change instead of via the 15 ms throttle — used by the brush so the stroke tracks the pointer even on a non-solo stack; the 变换 drag keeps the throttle); `DocumentLevel` (true ⇒ the op edits the whole document — `Source` is the composite and apply replaces the document instead of the active layer; used by crop/canvas/id-photo/slice); `ResultIsNewLayer` (true ⇒ `BuildResult`'s result is inserted as a **new layer** above the active one instead of replacing it; the editor reads it *before* calling `BuildResult`; used by 选区's 复制); canvas dispatch overrides; `RequestApply`/`ApplyRequested` for buttons that commit immediately; `ReusablePreview` (true ⇒ `RenderPreview` returns a bitmap the op still owns, so the editor shows it without copying/disposing — used by the brush); `TryGetPreviewDirtyRect(out rect)` (true ⇒ the bitmap returned by the last `RenderPreview` only changed in `rect` (preview coords), so a non-solo composite can redraw just that region — used by the brush; default false = whole); `WantsCanvasDrag` + `OnCanvasDrag(point, 0/1/2)` (true ⇒ the editor puts the canvas in drag mode and dispatches drags to the op — used by 变换); `WantsTransformBox` + `PaintCanvasOverlay(Graphics, layerToClient)` + `TransformCursor(layerPoint)` (true ⇒ the editor lets the op draw an overlay on the canvas and choose the hover cursor — used by 变换 for its handles; the op keeps working in layer coords and receives the drags via `OnCanvasDrag`); `OnCanvasHover(layerPoint)`/`OnCanvasDoubleClick(layerPoint)` (hover-without-button and left double-click, used by 选区's polygon tool); `OnDetach` (called only when the editor really switches away — `Attach` does not call it, so transient state like a selection survives apply/preview but is cleared on leave); `ResetState`; `DisposeResources`). `CompactLayout(gap)` groups the panel's absolutely-positioned children into rows (same `Top` within ~8px) and re-stacks the rows top-aligned with `gap`, preserving intra-row offsets — `DpiScaler` calls it for every `EditOpPanel` so shrinking the `EditOpUi` control heights doesn't leave large vertical gaps. `EditOpUi` is a small control-factory helper (Title/Caption/Slider/Combo/Button/Note) used by op constructors.
- `EditOpsAdjust.cs` — ops `BasicAdjustOp` (brightness/contrast/saturation/temperature/tint), `LevelsOp` (black/white/gamma + `AutoLevels`), `WhiteBalanceOp` (canvas sample / `AutoWhiteBalance`), `HslOp`, `StyleOp` (presets + strength), `EffectsOp` (13 `ImageFilters` effects).
- `EditOpsTone.cs` — ops `CurveOp` (per-channel `CurveEditor` → `TuningState.CurvePoints`), `LocalMaskOp` (radial/linear local mask, canvas-click center), `ToningOp` (posterize / duotone / gradient map), `LutOp` (`.cube` via `ImageTuning.TryLoadCube`).
- `EditOpsColorGrade.cs` — op `ColorGradeOp` (调色): a `TabControl` with **`Multiline = false`** (one row; when the tabs don't fit it shows scroll arrows that slide the tab strip instead of wrapping to two rows) hosting `BasicAdjustOp`/`LevelsOp`/`CurveOp`/`WhiteBalanceOp`/`HslOp`/`LutOp`/`ToningOp` (基础 / 色阶 / 曲线 / 白平衡 / HSL / LUT / 色调); only the selected tab participates in preview/apply (`RenderPreview`/`BuildResult`/`CanApply`/`HasPendingResult`/`LivePreview`/canvas dispatch all delegate to the active sub-op), switching tabs detaches the old sub and attaches the new one (before switching it raises `EditOpPanel.SubOpChanging`, which the editor answers with `ResolvePendingEdits()` so the current tab's unapplied调整 is applied/discarded/cancelled), and `OnResetState` resets **all** sub-ops. The sub-ops implement `HasPendingResult` (their identity check) so an untouched tab doesn't count as a pending edit.
- `EditOpsMore.cs` — ops `MattingOp`, `CropOp` (crop / exact 90° rotate / flip; tiled buttons that apply immediately via `RequestApply` so repeated clicks accumulate, plus a `RequestReset` button that restores the image snapshot taken when the tool was entered — `EditOpPanel.WantsEntrySnapshot`), `IdPhotoOp` (single photo or sheet tiling via `ImageLayout.BuildSheet`; the 尺寸 combo catalogs both ID-photo specs (一寸/二寸/护照/签证…) and print/paper sizes (5寸/6寸/7寸/8寸/A5/A4/A3/Letter…) at 300 DPI, each in **both 横 and 纵** orientations (e.g. `A4 纵 2480×3508` / `A4 横 3508×2480`), plus a 自定义… entry opening `CustomSizeDialog` (毫米@300DPI 或 像素) — `CurrentSize(out w,out h)` resolves the selection to the target pixel size), `ColorMatchOp` (reference image + `EstimateAdjustment`), `LocalOverlayOp` (multi-region feathered overlay; 覆盖位置 = 相对 maps the selection proportionally onto the overlay (crop) then scales that piece back to the base selection — handles overlays larger/smaller than the base; 绝对 uses the selection's exact pixel rect 1:1 to crop the overlay and paste at the same base position, no scaling), plus view-only `ColorToolOp`, `CompareOp` (left/right + top/bottom side-by-side, slider compare — `WantsCanvasDrag`/`WantsTransformBox` let the user drag the divider directly on the canvas, ratio = x/source width — and difference highlight; `CanApply == false`), `InfoOp` (`CanApply == false`).
- `EditOpsSlice.cs` — op `SliceCollageOp` (grid slice export via `ImageLayout.Slice`; collage with direction/columns/spacing/long-edge/background via `ImageLayout.Collage`).
- `EditOpsDraw.cs` — op `DrawOp` (绘画 / 标注): tools 直线/箭头/画笔/橡皮擦/模糊/马赛克/文字/形状 (矩形/圆角矩形/椭圆/三角形/五角星), with color picker, 粗细, 不透明度 (整笔 alpha，矢量图元写入 `Item.Color` 的 alpha，栅格笔刷在模糊后按 alpha 缩放 `CreateStamp`), 强度 (模糊半径 / 马赛克块大小), 字号, 填充 and 撤销一笔/清除全部. Two kinds of strokes are kept in one **ordered** `_strokes` list (vector `Item` / raster `Effect`) so a raster effect acts on everything drawn **before** it — the eraser can erase a not-yet-applied line. **Vector items** (line/arrow/pen/text/shapes) are recorded in **source coordinates**; **raster effects** (eraser/blur/mosaic) apply a soft brush mask to a persistent `_committed` bitmap. `_committed` is built incrementally in draw order (a completed vector item is **baked** into it via `BakeItem`, a live raster stroke stamps it, preview blending only the dirty rect); `_work` (= `_committed` + the in-progress vector `_current`, `ReusablePreview` so the editor shows it without owning it) is recomposed via `ComposeWork` and returned by `RenderPreview` (which also snapshots/clears the accumulated dirty rect for `TryGetPreviewDirtyRect`: a baked vector item via `BakeItem`→`ItemBounds`, a raster stamp via its mask rect, a freehand move via only the new `MarkSegmentDirty` segment, and a full rebuild — `RebuildFromStrokes`/undo/clear/reset — via `MarkDirtyWhole`). `BuildResult` clones `Source` and **replays `_strokes` in order** (`ApplyStrokesFull`: vector items re-drawn at 1:1, raster runs applied to the result, adjacent same-(kind,strength) effects merged into one group so each blur/mosaic runs once). 撤销一笔/清除全部 rebuild `_committed` by replaying `_strokes` over the base (`RebuildFromStrokes`). Uses the canvas brush events (`OnBrushPoint`, `LivePreview` + `ImmediatePreview` so the stroke refreshes synchronously and hugs the pointer). 文字 uses **in-canvas editing**: clicking overlays a **multiline** `CanvasTextBox` (an internal `TextBox` subclass that is truly transparent — it handles `WM_ERASEBKGND` by calling `ImageCanvas.PaintView` to draw the parent canvas image into its own DC, and the canvas handles `WM_CTLCOLOREDIT`/`STATIC` returning `NULL_BRUSH` so the edit never fills its own background) on the canvas plus a small ✓/✕ button pair (positioned via `ImageCanvas.ImageToClient`, font scaled by `ViewScale`); `Enter` inserts a newline, **✓ commits** into a text item (`✕`/`Esc` cancels). Blur no longer commits (so ✕ works); clicking elsewhere commits the previous box, switching ops commits silently (`CommitTextEditCore`), and apply/reset discards it. `Canvas.TextEditing` suppresses Space-pan while typing and `ViewChanged` repositions the box on zoom/pan. Note: don't dispose the old `Control.Font` when reassigning an *equal* font — WinForms ignores the assignment and you'd free the in-use font.
- `EditOpsTransform.cs` — op `TransformOp` (变换): move the active layer by dragging on the canvas (`WantsCanvasDrag`; `OnCanvasDrag` accumulates `_dx/_dy` in source px) plus `水平`/`垂直` (each 10–400%) and `旋转` (−180–180°) sliders, applied about the content centre via `Graphics` translate/rotate/scale. The transform box hugs the layer's **actual content**: `EnsureContent` caches `ImageFilters.ContentBounds(Source)` (bounding box of non-transparent pixels; falls back to the full layer when fully transparent) and `PivotX/PivotY` use its centre, so transparent margins don't inflate the handles. It is also the `WantsTransformBox` op: `PaintCanvasOverlay` draws an axis-aligned-then-rotated bounding box with 4 corner + 4 edge-midpoint handles and a rotation handle 22 client-px along the outward normal from the top edge midpoint (whether the offset fits is judged by the **top edge's** position relative to the canvas control, not the whole image's top margin; if there is no room outside — common after zooming in — the offset is flipped so the handle sits 22px **inside** the top edge rather than landing on the bounding box edge — `RotationHandleClient`/`QuadClient`, used by both drawing and hit-testing); `OnCanvasDrag(action 0)` hit-tests those handles in layer coords (`HitHandle`, tolerance 8 client px converted via `_previewScale * Canvas.ViewScale`; handle indices 0–3 corners, 4–7 edges, 8 rotation) and then either scales, rotates (drag the rotation handle about the content centre, angle normalised to ±180), or moves. Corner drags scale uniformly (both axes by the same factor relative to the drag-start scales), edge drags change only the matching axis (`ApplyScaleDrag` solves componentwise in the un-rotated frame; anchored to the opposite corner/edge, `_dx/_dy` adjusted so the anchor stays put); `TransformCursor` returns rotation-aware resize/move cursors; `LivePreview` is on so the box follows the pointer. Uses `ReusablePreview` (keeps one preview bitmap and redraws it in place, so a drag allocates nothing per frame) and renders the live preview with `HighQualityBilinear` (the full-res `BuildResult` still uses `HighQualityBicubic`). `RenderPreview` returns `null` at identity (so the editor shows the composite) and `BuildResult` returns the transformed layer bitmap (content pushed outside the canvas is clipped); 重置 returns to identity.
- `EditOpsSelect.cs` — op `SelectionOp` (选区): PS-style marquee/lasso family backed by an arbitrary-coverage mask (`ImageSelection`, layer pixels). Tools `矩形框选`/`圆形框选` (drag; `WantsCanvasDrag`), `画笔` (brush; `Canvas.BrushEnabled` + `OnBrushPoint`, radius from the 画笔 slider via `BrushRadiusSession`), `套索` (drag freehand), `多边形套索` (click vertices via `OnCanvasClick`, `OnCanvasHover` draws the rubber band to the cursor, `OnCanvasDoubleClick`/点回起点/`完成多边形` closes), `磁性套索` (drag with edge snapping — `EnsureLum` caches the source luminance; `Snap` searches a `SnapRadius()` window that is scaled from the 磁力 slider's **client-pixel** value via `Source/PreviewSource` and `Canvas.ViewScale` (so it stays usable on large downscaled images), and picks the best `gradient*200 - dist²` so real edges dominate while ties prefer the nearer pixel). A 运算 combo selects 新建/加选/减选/交集 (`ImageSelection.Combine`). `WantsTransformBox` is always true so `PaintCanvasOverlay` draws the committed mask as animated marching ants (`BuildOutline` traces a ≤800px downscale into merged edge runs; a 110 ms `Timer` advances the dash offset) plus the in-progress shape/polyline. Buttons 全选/反选/取消选择/删除/填充/复制/剪切/贴入 (`RequestApply` + `_pending` action; apply keeps the selection, `OnDetach` clears it). 复制 (action 4) returns `ResultIsNewLayer == true` and builds a document-sized transparent bitmap holding just the masked selection, so the editor inserts a new 选区复制 layer above the active one (via `EditSession.AddImageLayer`, which skips a redundant 1:1 resample when the bitmap is already document-sized); it also fills the clipboard so 贴入 still works, and 剪切 = clipboard + delete on the current layer. `CanApply`/`HasPendingResult` false and `RenderPreview` null (no pixel preview — actions are immediate), so it never raises `PreviewInvalidated`/sets the editor's `_opDirty`; the 羽化 slider is applied by `EffectiveMask` at action time. 贴入 scales the clipboard to the current selection with `WrapMode.TileFlipXY` (otherwise the scaled `DrawImage` samples outside the source and leaves a translucent white fringe around the pasted content).
- `LayoutCompact.cs` — `Compact(container, gap)` groups a container's absolutely-positioned (`Dock=None`) children into rows (same `Top` within ~8px) and re-stacks the rows top-aligned with `gap`, preserving intra-row offsets; `CompactAndFit(container, gap, bottomPad)` also shrinks the container's height to fit. `EditOpPanel.CompactLayout` delegates to it, and `BatchProcessPage`/`MultiSizeExportPage` call it at the end of their UI build to tighten the option `GroupBox`es after their control heights were reduced. Layout metrics are deliberately compact: op-panel content is ~250px wide (single-edit right column 300px), slider = caption at x10 + `TrackBar` at x78×132 + value label at x214; batch/export option columns are 280px wide (group boxes 256px). Watch these when changing widths — `Test51` asserts no op-panel/group-box child overflows its container (`Test48` asserts no overlaps).
- `BatchProcessPage.cs` — the `"批量处理"` tool page (file list/thumbnails + a scrollable options panel: 输出格式 / 尺寸 / 旋转翻转 / 重命名 / 水印). It does **not** use WinForms `Anchor` for its main layout: `DpiScaler` scales每个控件的绝对坐标，而 `Anchor` 又会按父容器尺寸二次调整边距，两者叠加会在高 DPI 下把右侧选项面板和底部控件推到页面外（曾出现"除了文件列表其他都不显示"）。改为重写 `OnLayout` → `RelayoutBatch()`：每次布局按当前 `ClientSize` 重新摆放顶部按钮（放不下自动换行）、文件 `ListView`、选项面板、输出目录组、进度条/状态/开始按钮；比例 `s` 取自某个顶部按钮的缩放后高度 `Height/22f`，因此与 DPI 无关。构造函数里 `ClientSize = new Size(990, 700)` 现在只是设计基准。`Test52` 断言 1×/1.25×/1.5×/2× 下所有控件都留在页面内。
- `BatchProcessPage.cs` (continued) — processing and thumbnails each run in their own `BackgroundWorker`. `BuildOptions()` snapshots the UI into a `BatchOptions` on the UI thread; the worker only touches that snapshot. A watermark image is preloaded on the UI thread and disposed in the worker's `finally`.
- `ImageEffects.cs` — `ColorMatrix` builders (`Brightness`, `Contrast`, `Saturation`, `Temperature`, `Tint`, `Grayscale`, `Sepia`, `Multiply`) and `PresetMatrix(name)`; in-place spatial effects (`Vignette`, `Soften`, `Sharpen`, `Grain`, `LightLeak`, `Frame`) that expect a 32bppArgb bitmap; and statistics (`ColorStats`/`MeasureStats`/`EstimateAdjustment`/`MatrixFromParams`) for color matching.
- `ImageFilters.cs` — no WinForms/WPF UI deps; heavier pixel filters operating on 32bppArgb bitmaps: `Clone`, `Mosaic`, `GaussianBlur` (3× separable `BoxBlur`), `MotionBlur`, `OilPaint`, `Sketch`, `Emboss`, `EdgeDetect`, `BackgroundBlur` (radial clear-zone blend), `Paper`, `Glow` (bright-pass + screen), `RoundedCorners`, `Circle` and `DropShadow` (both return new bitmaps), and `MaskBlend(base, effect, mask)` which lerps toward `effect` by the mask's alpha channel (used by `DrawOp`'s blur/mosaic brushes and `LocalOverlayOp`). `CopyPixels`/`PastePixels` are the LockBits helpers.
- `ImageUtil.cs` — generic WIC-backed image helpers: `LoadImage`, `CreatePreview` (downscales with `HighQualityBicubic` — noticeably sharper than bilinear for the large reduction ratios used here; the result is cached so the extra cost is paid once; the scaled draw uses `WrapMode.TileFlipXY` so the downscaled bitmap doesn't get a semi-transparent 1px border), `LoadThumbnail`, `Compose`, `MapRegion`, `ApplyColorMatrix`, `SavePng`, private `ToBitmap`. Always converts to `Bgra32` before copying pixels, so opaque images don't end up with alpha 0.
- `ImageCanvas.cs` — custom `Control` that displays an image letterboxed over a gray/white checkerboard (so transparent pixels read as transparent); the image/checker are painted in `OnPaintBackground` (not `OnPaint`) so a `WS_EX_TRANSPARENT` child control (the draw op's transparent text box) reveals the image behind it (the scaled image draw in `PaintView` uses `WrapMode.TileFlipXY` so the letterboxed image doesn't get a semi-transparent 1px border where it meets the checkerboard), and `OnPaint` draws only the selection/brush overlays and supports rubber-band selection in image pixel coordinates (`ReadOnly` mode shows a non-editable selection); when the selection is editable (not `ReadOnly`/brush/drag) it draws 8 handles (4 corners + 4 edge midpoints, `SelectionHandlePoints`) and the user can drag inside the selection to move it or drag a handle to resize it (`OnMouseDown`/`OnMouseMove`/`OnMouseUp` route to `UpdateSelectionEdit`, clamped to the image with a 1px minimum; `HitSelectionHandle`/`HandleCursor`/`SelectionCursor` provide the hit-testing and resize/move cursors), raising `SelectionChanged` on release; `LockAspect > 0` constrains the selection to a fixed width/height ratio (only while rubber-banding); `PixelClicked` reports the clicked image-pixel coordinate (used for white-balance sampling and local-mask center). `BrushEnabled` switches mouse handling to freehand painting: `BrushStarted`/`BrushMoved`/`BrushFinished` report image-pixel points, and a `BrushRadius` (in displayed-image pixels) circle follows the cursor. `DragEnabled` switches to drag-to-move (`SizeAll` cursor): `DragStarted`/`DragMoved`/`DragFinished` report image-pixel points. `PointerMoved` reports every button-less mouse move (used by 选区's polygon rubber band) and `PointerDoubleClicked` reports a left double-click (used by the polygon tool to close). `OverlayPainter`/`CursorProvider` let the active op draw an overlay on top (e.g. the 变换 box) and choose the hover cursor (client/displayed-image coords). In drag mode the dispatched/hover point is **unclamped** (`ControlToImageRaw`) — it may fall outside the image bounds in the letterbox margin — so a transform handle drawn there stays grabbable; click/selection/brush still use the clamped `ControlToImage`. Selection, brush and drag modes are mutually exclusive. View transform: mouse wheel zooms (`_zoom`, cursor-anchored, clamped 0.1–16×) and holding **Space** + left-drag (or middle-drag) pans (`_panX/_panY`, clamped to the image edges) — implemented via `ComputeLayout()` which derives `_scale = fit*_zoom` and `_imageRect` from zoom+pan; `ZoomEnabled=false` disables it (used by the overlay thumbnail). A global `IMessageFilter` watches the Space key only while the mouse is over the canvas (skipped while `TextEditing`); `ImageToClient`/`ViewScale`/`ViewChanged` let an op overlay controls (e.g. the draw op's text box) and keep them aligned on zoom/pan; the view resets when the image size changes but survives same-size preview refreshes. `SetImage` compares against a remembered `_lastImageW/H` (never reads `_image`, which the editor may already have disposed).

Used by `LevelsOp`/`WhiteBalanceOp`/`HslOp`/`InfoOp`.
- `HistogramView.cs` / `CurveEditor.cs` — custom `Control`s for the histogram display and draggable curve editing (add/drag/right-click-delete control points).

- `ImageBlend.cs` — `Blend(base, overlay, BlendMode, opacity)` scales the overlay to the base and applies one of 11 blend modes per pixel (keeps base alpha); `Composite(base, overlay, BlendMode, opacity)` is the alpha-correct source-over version (used by `MergeDown`); `CompositeInto(acc, overlay, …)` is the in-place variant that blends the overlay **into** `acc` (which doubles as base and output) using two per-thread reusable scratch buffers, so `EditSession.Composite`/`CompositePreview` allocate one accumulator and blend each layer in place (no per-layer bitmap/GC churn); an offset overload places the overlay at `(offsetX, offsetY)` first (used for live layer-move preview).

- `MultiSizeExport.cs` + `MultiSizeExportPage.cs` — the `"批量导出"` tool page; `ComputeSize` (fit/stretch), `ResizeTo`, and `WriteIco` (writes a multi-size .ico with PNG-compressed entries). The page collects files (buttons + drag-drop), size checkboxes, format, and exports each file to each size plus an optional `.ico`.
- Adding a new single-image operation: subclass `EditOpPanel`, add it to `SingleEditPage._ops` and the parallel `names` array; implement `RenderPreview`/`BuildResult` (+`CanApply`) and any canvas dispatch. Layer ops edit the active layer (same doc size); override `DocumentLevel` only if the op changes the document size/whole-document layout. Adding a new batch tool: subclass `ToolPage` and add it to the `ToolHostPage("批处理", …)` array in `MainForm`. Namespace is `ImageToolbox`.
- WebP decoding uses **WIC** (`BitmapDecoder` / `BitmapImage`), not `System.Drawing`. GDI+ has no WebP codec: `Image.FromFile("*.webp")` throws `OutOfMemoryException`. Do not switch to System.Drawing for decoding.
- Decoding depends on the OS WebP WIC codec (built into Windows 11; Windows 10 needs the "WebP Image Extensions" Store package).
- WPF imaging objects must stay on the thread that creates them. `LoadThumbnail` runs on the worker thread and hands back only a `System.Drawing.Bitmap`.

## DPI / manifest

- `app.manifest` is embedded via `/win32manifest` for DPI awareness and must stay wired into `build.ps1`. Without it, Windows bitmap-stretches the window and text is blurry at 125%/150% scaling.
- `app.ico` is embedded via `/win32icon`; `MainForm` also sets its title-bar icon from `ExtractAssociatedIcon` (WinForms derives `ICON_SMALL`/`ICON_BIG` from it). Regenerate the `.ico` with Pillow if needed. Note: don't reload the icon per-DPI in code — requesting a size that isn't an actual entry in the `.ico` (`new Icon(stream, w, h)`) makes GDI+ stretch an existing size and the title-bar icon looks blurry.
- All controls use `AutoScaleMode.None` (WinForms auto-scaling off). Instead `DpiScaler.Apply(root, scaleRootSize)` runs in `MainForm.OnLoad` (and `NewImageDialog.OnLoad`, with `scaleRootSize=true`): it walks the tree; for each `EditOpPanel` it first calls `CompactLayout(6)` (in design pixels), then, when the DPI ≠ 96, recursively multiplies every control's `Location`/`Size`/`Padding`/`Margin`/`MinimumSize`, docked thicknesses, and `TableLayoutPanel` absolute row/column styles by `dpi/96` — but **not** `Font` (a 9pt font already renders 2× at 200% DPI, so scaling it again would double). This is deterministic and avoids the WinForms `AutoScaleMode.Dpi` pitfalls (nested `UserControl`s double-scaling, or not scaling at all) that clipped/overlapped controls at 200%.
